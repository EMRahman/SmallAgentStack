00 / Why

I wanted an agent,
not an appliance.

My OpenClaw 2.0 upgrade did not work. After a fresh install, I found jobs I could not deactivate and heartbeat activity creating costs I did not need. So I replaced the bundle with four small, understandable pieces.

This is not a drop-in clone. It is a simpler pattern: Pi does the thinking, normal operating system tools handle timing, and optional interfaces can be added or removed independently.

“If a task should run, I schedule it. If it should not run, nothing calls the model.”
01 / The stack

Small pieces, clear jobs

Four tools.

Start with Pi. The other three pieces are optional. Each can be understood, inspected, and replaced without rebuilding everything else.

02 / Set up

A calm first ten minutes

Begin with one piece.

These commands are for macOS and Linux. Pi also supports Windows; use the official platform guide, and use Task Scheduler instead of cron.

i

Before you begin: install Node.js. Pi itself has lighter needs, but the full stack—including Livecraft—currently needs Node.js 24 or newer.

1

About 2 minutes

Install Pi

Open Terminal, paste this line, and press Return.

npm install -g --ignore-scripts @earendil-works/pi-coding-agent

The --ignore-scripts flag follows Pi’s safer official npm install path.

2

About 3 minutes

Choose where Pi works

Create a home for your assistant’s notes and projects, then launch it there.

mkdir -p ~/PiWorkspace
cd ~/PiWorkspace
pi

This becomes Pi’s working folder. Pi still runs with your user account’s permissions, so use backups and review sensitive actions.

3

About 3 minutes

Connect your model

Inside Pi, type /login. Choose a supported subscription you already have, or enter an API key for your preferred provider.

✓

Success looks like: Pi accepts “Tell me what folder you are working in” and answers without an authentication error.

4

Any time

Leave and come back

Pi saves sessions automatically. These two commands are the habit worth remembering.

pi -c Continue your latest session
pi -r Browse and reopen any session
03 / Add what you need

The optional layers.

Get comfortable with Pi first. Then add one interface at a time.

A

For a browser and cost view

Add Livecraft

Fork Livecraft on GitHub if you want your own editable version, then use your fork’s address below. If you only want to try it, clone the original repository.

git clone https://github.com/sebastienservouze/pi-livecraft.git
cd pi-livecraft
npm install
npm run dev

Then open 127.0.0.1:5173. “Local” means the interface runs on your computer.

B

For access from your phone

Add TelePi

Ask Telegram’s @BotFather for a bot token, then run the guided setup. It asks for that token, your numeric Telegram ID, and your workspace.

npm install -g @futurelab-studio/telepi
telepi setup
telepi status

Guided service installation currently targets macOS and Linux. Keep the bot token private and allowlist only your own numeric ID.

C

For a task at a known time

Add one cron job

First run command -v pi to find Pi’s full path. Then run crontab -e and add a line like this, replacing both example paths with your own. This direct route creates a Pi session for Pi and Livecraft; it does not send the result to Telegram.

Keep it observable. Give the run a name, use absolute paths, and save its plain-text output to a log.
# Weekdays at 8:00am
0 8 * * 1-5 cd /Users/you/PiWorkspace && /full/path/to/pi --name "morning brief" -p "Read TASKS.md and prepare today's brief. Do not send or publish anything." >> /Users/you/PiWorkspace/cron.log 2>&1
↗

To make a cron job appear in Telegram

Use TelePi’s dropbox

TelePi calls this the External Prompt Inbox. Enable a watched folder once, then have cron place a .txt prompt inside it instead of launching Pi directly.

1 / Create the inbox
mkdir -p /Users/you/PiWorkspace/telepi-inbox
2 / Add this to ~/.config/telepi/config.env, then restart TelePi
TELEPI_PROMPT_INBOX_DIR=/Users/you/PiWorkspace/telepi-inbox
Restart: macOS launchctl kickstart -k gui/$UID/com.telepi · Linux systemctl --user restart telepi.service
3 / Make cron drop the prompt safely
# Write as .pending, then rename when complete
0 8 * * 1-5 /bin/echo 'Read TASKS.md and prepare today’s brief. Do not send or publish anything else.' > /Users/you/PiWorkspace/telepi-inbox/morning-brief.pending && /bin/mv /Users/you/PiWorkspace/telepi-inbox/morning-brief.pending /Users/you/PiWorkspace/telepi-inbox/morning-brief.txt

TelePi processes one .txt file at a time, sends it to the root Telegram chat for the first allowlisted user, and removes the file after accepting it. If the chat is busy, the file stays queued for the next check.

Note A session that is still being written by a cron run may appear incomplete in Livecraft until that run finishes.

macOS + iCloud

An editable brief and a living result

Let an Apple Note
be the job.

A cron entry can launch a small runner script while the actual instructions stay in an Apple Note. Change the note whenever the brief changes—there is no need to rewrite the schedule. The runner reads that note, asks Pi to do the work, then replaces or appends to a second Apple Note.

If the automation Mac uses a different Apple Account, share the output note with the Apple Account on your iPhone. Updates made by the agent account are then collaboration activity, so Notes can notify the iPhone when alerts are enabled.

OPENCLAW → PI MIGRATION PROMPT 
You are helping me migrate from OpenClaw to a smaller, modular Pi setup on this computer.

The target setup is:
- Pi for agent conversations and locally saved sessions
- Pi Livecraft only if I want a browser and per-session cost view
- normal system cron (macOS/Linux) or Task Scheduler (Windows) only for jobs I explicitly approve
- TelePi only if I want Telegram access, using its External Prompt Inbox/dropbox for scheduled jobs that should appear there
- no AI heartbeat and no recreated background model polling

Work in two phases. PHASE 1 MUST BE READ-ONLY.

PHASE 1 — AUDIT AND PLAN
1. Confirm the operating system, my current working folder, and that the `pi` command works.
2. Find OpenClaw's actual config and state locations safely. Respect OPENCLAW_CONFIG_PATH and OPENCLAW_STATE_DIR if set. Otherwise inspect the normal ~/.openclaw location. If the OpenClaw CLI exists, you may use read-only commands to locate its config.
3. Determine each configured OpenClaw agent workspace. The usual default is ~/.openclaw/workspace, but do not assume it.
4. Inventory, without changing anything:
   - AGENTS.md, SOUL.md, IDENTITY.md, USER.md and MEMORY.md
   - dated memory files and other user-authored Markdown
   - skills containing SKILL.md, and any custom prompts or scripts
   - scheduled jobs, cron definitions and HEARTBEAT.md
   - channel integrations that I may want to replace
   - existing ~/.pi/agent files that must be preserved or merged
5. Never print, copy, or expose API keys, bot tokens, OAuth files, credential stores, or secret values. Report only that a credential category exists.
6. Treat OpenClaw session databases/JSONL and Pi sessions as incompatible. Do not try to place OpenClaw sessions in Pi's session directory.
7. Present a plain-language migration table with: item found, proposed destination, action (copy / merge / archive / skip), risk, and whether I must decide.
8. Propose a new workspace path (default ~/PiWorkspace) and a timestamped backup path. Explain exactly what you want to create or edit.
9. STOP and ask for my approval before making any change.

PHASE 2 — ONLY AFTER I APPROVE THE PLAN
10. Make a timestamped backup of every source file that will be transformed and every existing destination file that will be changed. Never delete or move the originals.
11. Create the approved Pi workspace. Preserve useful OpenClaw profile and memory Markdown in a clearly named reference/ archive inside it.
12. Build or carefully merge an AGENTS.md for Pi. Distil durable instructions from AGENTS.md, SOUL.md, IDENTITY.md and USER.md; remove OpenClaw-specific tool claims; add short pointers to archived memory instead of loading everything into every prompt. Show me the proposed merged text before saving it.
13. Copy only reviewed, compatible skills into the project-local .pi/skills/ directory. Skills and extensions can execute or instruct powerful actions, so summarize each one and ask before enabling it. Do not copy generated caches or dependencies.
14. Convert useful recurring prompts into project-local .pi/prompts/*.md where appropriate. Keep names simple and document what each command does.
15. Do not recreate HEARTBEAT.md or any recurring heartbeat. Extract any genuinely useful tasks from it into a disabled list of possible scheduled jobs.
16. For every OpenClaw scheduled job, first ask where its instructions should live and where its result should appear. For Pi/Livecraft, propose an explicit direct Pi runner and cron/Task Scheduler entry with absolute paths, a named session, minimal permissions, and a log file. For Telegram, do not launch a separate Pi session directly: propose TelePi's External Prompt Inbox/dropbox, configure TELEPI_PROMPT_INBOX_DIR, and have the scheduler atomically place a .txt prompt there. Explain that TelePi sends inbox prompts to the root chat for the first allowlisted user. On macOS, if I explicitly choose Apple Notes, propose a tightly scoped runner that reads one exact instructions note and updates or appends one exact output note; run it manually for Automation permission before proposing cron or a user LaunchAgent. Do not install or activate any schedule until I approve that job individually.
17. Do not migrate provider credentials. Help me use Pi's /login flow or set a new API key myself. Do not migrate Telegram bot tokens; if I choose TelePi, use its official guided setup and ask me to enter the secret directly.
18. Keep old OpenClaw conversations as a read-only archive. If I select important conversations, summarize them into clearly labelled Markdown notes with source references; never claim they are native Pi sessions.
19. Verify the result without making a paid model call unnecessarily: show the created tree, check files and commands, and give me the exact commands for `pi`, `pi -c`, and `pi -r`.
20. Finish with four lists: migrated, transformed, deliberately skipped, and still awaiting my decision. Also list every mechanism in the new setup that can trigger a model call.

Safety rules:
- Preserve and merge; never overwrite blindly.
- Do not uninstall, disable, stop, or reconfigure OpenClaw during this migration.
- Do not activate cron, Task Scheduler, TelePi, Livecraft services, packages, skills, or extensions without separate, explicit approval.
- Pause if paths are ambiguous, files conflict, or a command would need administrator privileges.
- Use the current official documentation for any install command whose package name or requirements may have changed.
Read it before you paste it—this is a set of instructions, not a magic importer.

06 / Questions

Plain answers

Before you switch.

Do I need all four tools?+

No. Pi is the only required piece. Add Livecraft for a browser, cron for scheduled tasks, and TelePi for Telegram. Leaving a piece out is part of the design.

Does this make AI usage free?+

No. Your chosen model or subscription determines the price. The benefit is legibility: model calls begin when you ask Pi something, message TelePi, or launch a scheduled Pi task—not from a heartbeat in this design.

Can I move my old conversations?+

Keep them as a read-only archive. The two systems do not share a native session format. You can ask Pi to summarise selected conversations into Markdown notes, but that is a reference, not a resumed session.

Is Pi sandboxed?+

No. Pi runs locally with your user account’s permissions. Start it in a folder you understand, keep backups or use Git, review third-party skills, and read commands before approving sensitive work.

Can I see a cron session while it runs?+

Usually, but Livecraft may briefly show only part of a session while cron is still generating it. Wait for the run to finish, then reopen or refresh the session.

How does a cron job appear in Telegram?+

It must use TelePi’s External Prompt Inbox—the dropbox described above. Cron writes a completed .txt prompt into the watched folder; TelePi picks it up, runs it in the root Telegram chat for the first allowlisted user, and removes the file after accepting it. A normal direct pi -p cron job remains visible in Pi and Livecraft but does not announce itself in Telegram.

Can Apple Notes hold the job and its results?+

Yes, on macOS. A narrowly scoped runner can read one named instructions note, launch a named Pi session, and replace or append one named output note. Share the output note from the automation Mac’s Apple Account with the account on your iPhone to make updates collaboration activity. Notes notifications and per-note alerts must remain enabled; Focus settings can still suppress them.

When should I uninstall OpenClaw?+

Not during migration. First verify your Pi instructions, important files, chosen schedules, and messaging flow. Keep a backup, then follow OpenClaw’s current official removal instructions separately.
